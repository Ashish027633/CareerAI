## 6. Abstract
In today's highly competitive job market, students struggle to optimize their resumes for Applicant Tracking Systems (ATS), while recruiters face an overwhelming volume of applications. CareerAI is an AI-driven placement platform that bridges this gap. It automates resume parsing via NLP, provides actionable student feedback, and utilizes TF-IDF to match candidate resumes directly to job descriptions, significantly reducing manual screening time for placement cells.

## 7. Introduction & Problem Statement
The manual resume evaluation process is tedious, error-prone, and slow. Existing placement portals function as basic job boards, requiring students to manually enter exhaustive profile details and offering no intelligent analysis of uploaded resumes. Recruiters must manually read every resume to verify qualifications, resulting in a high turnaround time. CareerAI aims to replace this archaic system with an intelligent, automated ranking ecosystem.

## 8. System Architecture
CareerAI uses a microservices-inspired monolithic structure:
- **Frontend**: A React.js SPA providing role-specific dashboards.
- **Gateway/Backend**: A Java Spring Boot application handling JWT authentication, MySQL persistence, and role-based routing.
- **AI Engine**: A Python FastAPI service specializing in PDF parsing (PyMuPDF) and NLP TF-IDF matching.

## 9. Technology Stack
- **Frontend**: React.js, Tailwind CSS
- **Backend**: Java 17, Spring Boot 3.2, Spring Security (JWT)
- **AI Microservice**: Python, FastAPI, PyMuPDF, Scikit-Learn
- **Database**: Aiven MySQL 8+
- **Cloud Infrastructure**: Render (Backend/Python), Vercel (Frontend)

## 10. Implementation Details
The project was divided into 5 modules:
1. **Frontend UI**: Built with responsive Tailwind CSS.
2. **Backend Authentication**: Secured via BCrypt and JWT.
3. **Database Core**: Mapped via Spring Data JPA with `ddl-auto=update`.
4. **Resume Vault**: Secure BLOB storage preventing direct public access to sensitive documents.
5. **AI NLP Engine**: Python algorithms that tokenize PDFs and calculate cosine similarity (TF-IDF) against job descriptions.

## 13. Limitations & Future Enhancements
- **Limitations**: Currently relies on a Python microservice; any network latency between the Java backend and Python service can delay resume analysis.
- **Future Enhancements**: Implement LLMs (e.g., OpenAI/Gemini APIs) for deeper semantic understanding beyond simple TF-IDF keyword matching.
